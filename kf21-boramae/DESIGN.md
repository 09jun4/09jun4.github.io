# KF-21 BORAMAE — 설계 메모

3D 전투기 슈팅 MVP. Three.js + Vanilla JS(ES Modules) + Vite. 주소: `https://09jun4.github.io/kf21-boramae/`

## 1. 실행 · 배포 방식 (결정 사항)

- 이 저장소는 빌드 없이 `main`에 올리면 바로 GitHub Pages로 나가는 구조다. 그래서 **배포본 = 소스 그대로**로 했다.
  - `index.html`의 `importmap`이 `three`를 `js/vendor/three.min.js`(한 파일로 묶어 둔 three.js)로 연결한다.
  - 나머지는 브라우저가 `src/`의 ES 모듈을 직접 읽는다. 코드를 고치고 push하면 그대로 배포된다.
- Vite는 개발 도구로 쓴다: `npm run dev`(개발 서버), `npm run build`(한 파일로 묶은 `dist/`, 선택), `npm test`(Vitest 단위 테스트), `npm run smoke`(Playwright 스모크), `npm run vendor`(three.js 다시 묶기).
- 외부 3D 파일·이미지·폰트는 없다. 모델·구름·지형·효과는 모두 코드로 만든다.
- 디버그 훅 `window.__debug`는 개발 서버이거나 주소에 `?debug=1`이 있을 때만 켜진다(`src/core/debug.js`).

## 3. 핵심 알고리즘

- **게임 루프**: 누적기 방식 고정 타임스텝(60Hz). 프레임 델타는 0.1초로 상한(탭 복귀 시 시간 점프 방지). 렌더는 이전/현재 상태를 `alpha`로 보간.
- **비행 모델**: 상태는 (위치, 요, 피치, 시각 롤, 속도). 입력 → 목표 각속도 → 지수 감쇠로 실제 각속도(관성). 속도는 `추력−항력`을 순항속도로 끌어당기는 스프링 + 중력 성분(상승 감속/하강 가속) + 선회 항력. 속도 하한 근처에서는 상승 권한이 줄고 기수가 숙여진다(실속 사망 없음). 고도 하한·상한은 허용 피치 범위를 부드럽게 좁혀서 처리한다.
- **원점 재배치**: 플레이어가 원점에서 일정 거리 이상 벗어나면 모든 개체를 x·z로 되돌린다(y는 고도라 범위가 한정됨). 지형·구름은 누적 오프셋을 유니폼으로 받는다.
- **구름**: `InstancedBufferGeometry` 1~2 드로우콜. 구름 묶음 위치를 버텍스 셰이더에서 카메라 기준으로 순환(wrap)시켜 CPU 갱신 없이 무한 하늘을 만든다. 가장자리에서는 크기를 줄여 튀는 현상을 숨긴다.
- **원경 지형**: 격자 1장. 버텍스 셰이더에서 월드 좌표 노이즈로 높이를 만들고, 프래그먼트에서 미분으로 플랫 셰이딩 + 거리 안개.
- **기관포**: 카메라→커서 레이로 조준점을 구하고, 그 레이에 대해 적기 구(거리 비례 보정 반경)와 교차 판정(즉시 판정). 예광탄은 총구→조준점으로 그리는 연출.
- **미사일 락온**: 화면 중심 기준 각도 반경 안의 적 중 가장 중심에 가까운 적을 추적, 유지 시간 누적으로 락온. 반경 이탈 시 즉시 초기화.
- **미사일**: 실제 이동 발사체. 목표 방향으로 초당 최대 선회각 제한 회전, 수명·근접 신관.
- **적 AI**: 상태(접근/공격/이탈/회피/복귀) + 목표 방향을 각속도 제한으로 따라가는 조향 + 적기 간 분리 벡터. 동시 공격 수 제한(공격 토큰)으로 공정성 유지.
- **메모리**: 메시·풀은 시작할 때 한 번만 만들고 미션마다 상태만 초기화한다. 프레임 중 할당 없음(임시 벡터 재사용).

## 5. 결정 사항 (명세에 없어서 정한 것)

- **미사일 락온 범위의 중심은 화면 중심**이다(명세의 "화면 중심 기준"). 기관포는 마우스로 자유 조준, 미사일은 기수를 적기 쪽으로 돌려야 락온된다. 두 조준 방식이 독립적이고 역할이 갈린다.
- **마우스 감도**: 포인터락을 쓰지 않으므로, 조준 커서를 화면 중앙 기준으로 `감도` 배만큼 움직이는 방식으로 구현했다(1.0이면 실제 커서 위치).
- **과열 잠금 2.5초 동안에도 냉각은 진행**된다(쏘지 않는 동안 초당 30%). 잠금이 풀리면 약 25%에서 다시 쏠 수 있다.
- **미사일은 클릭하는 순간에만 발사**된다(누르고 있어도 연달아 나가지 않는다).
- **충돌로 파괴된 적기도 격추로 센다.**
- **적 탄은 실제 발사체**다(피할 수 있다). 조준은 탄 비행시간과 플레이어 가속도까지 반영해서, 같은 방향으로만 계속 돌거나 올라가면 맞는다.
- **고도 상한(9,500m)**을 뒀다. 속도 저하와 함께 "무한 상승으로 도망"을 막는다.
- **적기 식별**: 붉은 외곽선(화면 약 1.5픽셀 고정) + HUD의 붉은 모서리 상자. 모델은 실물보다 1.35배.
- **피치 한계 ±75°**: 루프(수직 넘김) 기동은 없다. 요+시각 롤 조작 체계에서 방향 감각을 잃지 않게 하기 위해서다.
- **설정의 계정 연동**: 마우스 감도·흔들림·시점은 계정에 저장하고, 그래픽 품질은 기기마다 다른 게 자연스러워 이 기기 값만 쓴다.
- **재시작**은 브리핑 없이 같은 미션을 바로 다시 시작한다.

## 7. 성능·메모리 측정값

`node tests/perf.cjs` (미션 3 + 적기 8대 + 연사 + 폭발 4개가 겹친 순간의 최대값):

| | 드로우콜 | 삼각형 | 예산 |
|---|---|---|---|
| 높음 | 31 | 약 116k | 150 / 200k |
| 낮음 | 29 | 약 74k | 80 / 100k |

- 미션 시작→전투→종료를 12회 반복한 전후: 지오메트리 23→23, 텍스처 1→1, 셰이더 15→15, JS 힙 +0.15MB(증가 추세 없음).
- 그림자·포스트프로세싱 없음. 구름·파티클·예광탄·적 탄은 InstancedMesh, 미션마다 재생성하지 않음.
- **FPS는 개발 환경(GPU 없는 서버, 소프트웨어 렌더링)에서 잴 수 없었다.** 실제 노트북에서의 60/45FPS 목표는 드로우콜·삼각형 예산과 자동 품질 조절로 대비했지만 실기 측정은 하지 못했다. `?debug=1` 뒤 콘솔에서 `__debug.showFps()`로 확인할 수 있다.

## 8. 알려진 한계

- **랭킹 부정 방지는 완전하지 않다.** 점수를 클라이언트가 올리는 구조라 조작된 요청을 막을 수 없다. 보안 규칙에서 타입·범위·점수식(1000×적기 수 + 남은 시간×10)과 최소 시간(8초)을 검증하고, 관리자가 랭킹 창에서 기록을 지울 수 있게 해서 대응한다.
- **보안 규칙은 실행 검증하지 못했다.** 로그인·이관·닉네임·랭킹 흐름은 가짜 SDK로 확인했고, 규칙 자체는 실제 Firebase 프로젝트에 게시한 뒤 확인이 필요하다.
- **등급**: 명세의 비율(S 90% / A 75% / B 55%)과 점수식을 그대로 쓰면, 전원 격추만으로 기준 점수의 약 77%가 되어 성공 시 등급은 항상 A 이상이다. 비율은 `src/data/grades.js`에서 바꿀 수 있다.
- **닉네임 금칙어**는 짧은 목록으로 거르는 수준이다.
- **조작감·난이도는 사람이 아니라 자동 조종으로 검증했다.** 수치 기준(반응 시간, 지속 상승각, 수평 복귀 등)은 단위 테스트로 확인했지만, 손맛에 대한 최종 판단은 실제 플레이가 필요하다.
- 사운드는 범위 밖이라 `core/audio-stub.js`의 `audio.play(name)` 호출 지점만 있다.
- 모바일 조작은 지원하지 않는다(범위 밖).

# 비주얼 업그레이드 (MVP 이후)

게임 규칙(조작·무장·적 AI·미션·점수·로그인·랭킹)은 그대로 두고 비주얼만 올렸다. MVP 명세에서 덮어쓴 항목: 후처리(높음·최고만 허용), 랜딩기어·이륙 연출, 활주로 시작, 이륙 구간의 지면, 성능 예산.

## 9. 그래픽 프리셋

| | 낮음 | 높음 | 최고 |
|---|---|---|---|
| 기체 | 기존 로우폴리(+기어) | 하이폴리 약 9.9만 삼각형 | 약 21만 삼각형 |
| 조종석 | 기존 | 하이폴리 + MFD + HUD 유리판 | 같음(분할·텍스처 해상도 ↑) |
| 적기 | 기존 | 약 4.0만 | 약 7.9만 + 불꽃 셰이더 |
| 재질 | 플랫 셰이딩 | PBR + 환경맵 + 절차 텍스처 2048 | 4096 |
| 구름 | 로우폴리 덩어리 | 부드러운 빌보드 3겹 | 5겹 |
| 파티클 | CPU 인스턴싱 | GPU 셰이더 7,000 | 16,000 |
| 후처리 | 없음 | 블룸·플레어·톤매핑 | + 모션 블러 |
| 그림자 | 없음 | 기체만 1024 | 2048 |

- 정의는 `src/data/quality.js`. 프리셋마다 모델을 통째로 바꾼다(LOD 없음). 높음·최고는 같은 생성 함수에 `detail`만 다르게 넘긴다.
- 전환은 `src/core/visuals.js`가 맡는다: 이전 모델·재질·텍스처·환경맵을 dispose하고 새로 만든다. 구름·지형·파티클 백엔드·후처리 타깃도 같이 바뀐다.
- **첫 실행 벤치마크**(`src/core/benchmark.js`): 인스턴싱 구 약 38만 삼각형을 1280×720 타깃에 최대 2초 그려 프레임 시간의 중앙값으로 고른다(4.5ms 미만 최고, 11ms 미만 높음, 그 외 낮음. 소프트웨어 렌더러는 바로 낮음). 사용자가 직접 고르면 다시 재지 않는다.
- 자동 품질 조절은 프리셋을 한 칸씩 내린다: 최고 → 높음 → 낮음 → min(해상도 0.75배).
- 설정 저장 형식 v2. v1의 `quality` 값은 의미가 달라서(둘 다 로우폴리) 버리고 벤치마크를 다시 한다.

## 10. 텍스처: 절차 생성을 고른 이유와 시작 시간

- 기체 텍스처(색·노멀·거칠기/금속성)는 실행할 때 캔버스에 그려 만든다(`src/entities/hi/textures.js`).
- **이유**: (1) 저장소에 이미지 파일을 두지 않아도 되고(외부 파일 금지 조건), (2) 도색 3종과 해상도를 실행 중에 바꿀 수 있고, (3) 패널 라인·리벳·마킹이 형상 표(`kf21-shape.js`)의 좌표를 그대로 써서 모델과 어긋나지 않는다.
- 아틀라스 구역: 날개류(위에서 본 반쪽, 좌우 공유) / 동체(둘레로 펼침) / 수직면 / 민무늬. 동체를 둘레로 펼쳐서 옆면에서도 노멀맵이 뭉개지지 않는다.
- 수직미익은 안팎 면이 같은 그림을 쓰므로 글자 대신 좌우 대칭 표식만 넣었다. 동체 글자는 좌우에서 모두 바로 읽히게 방향을 뒤집어 그린다.
- **시작 시간**(개발 환경 측정, 소프트웨어 렌더링이라 실제 기기는 더 빠르다): 낮음 약 0.4초(로딩 바 없음), 높음 약 1.3~2.6초, 최고 약 2.9초. 높음·최고는 그동안 로딩 바와 조종 팁을 보여 준다.

## 11. 하이폴리 생성 방식

- `src/entities/hi/surface.js`: 매개변수 곡면 격자·로프트·튜브·구·상자를 인덱스 지오메트리로 쌓는다. 면 방향은 격자 중심 기준으로 자동 정렬, 닫힌 고리의 이음매는 법선을 평균한다.
- 동체는 형상 표를 스플라인으로 이어 단면을 만들고, 단면 지수(`CHINE_POWER`)로 차인의 날카로움을 조절한다. 날개·미익은 NACA 대칭 익형 단면 로프트.
- 조종면(플랩·에일러론·수평미익·러더·에어브레이크)은 힌지 좌표계로 구워 x축 회전만으로 꺾인다.
- 노즐 꽃잎의 개폐와 열 변색은 `onBeforeCompile`로 표준 재질 셰이더에 끼워 넣었다(꽃잎 끝 비율 속성 + 유니폼 2개).
- 1인칭에서는 외형을 숨기지 않고, 조종석 자리의 동체 외피만 클리핑 평면 6개(교집합)로 잘라낸다. 그래서 날개 끝과 기수가 보인다.
- HUD: 1인칭(하이폴리)에서는 자세·속도·고도 기호를 기체에 고정된 가상 면(눈앞 6m, ±12°)의 캔버스 텍스처에 그린다. 머리가 움직이면(G 쏠림·선회) 조종석 틀에 대해 미세하게 어긋난다. 조준점·락온·화살표·체력·무장은 화면 기준이라 2D 오버레이에 남겼다.

## 12. 후처리·파티클 파이프라인 (`src/world/post.js`, `src/entities/gpu-particles.js`)

1. 장면 → HalfFloat + MSAA 4x 타깃(깊이 텍스처 포함)
2. 장면 색을 두 번째 HDR 타깃에 복사하고 그 위에 파티클 층을 그린다. 파티클은 1의 깊이 텍스처를 읽어 가려진 곳은 버리고 맞닿는 가장자리는 부드럽게 한다(소프트 파티클). MSAA 타깃은 해상 뒤 내용이 버려져서 이어 그릴 수 없어 이렇게 했다.
3. 블룸: 밝기 1.05 이상만 뽑아 절반씩 줄였다 키우며 더한다(불꽃·항법등·계기판·HUD만 번진다).
4. 합성: 렌즈 플레어(해 위치의 깊이를 읽어 가려지면 끈다) + ACES(원색과 4:6으로 섞어 낮 하늘 색 유지) + 색보정 + 폭발 가장자리 섬광
5. 최고만: 화면이 빨리 돌 때 이전 프레임을 최대 32% 섞는 약한 모션 블러

GPU 파티클은 생성할 때만 CPU가 값을 쓰고(링 버퍼), 움직임은 버텍스 셰이더가 계산한다. 낮음은 기존 CPU 인스턴싱 파티클을 그대로 쓴다.

## 13. 이륙 연출 (`src/data/takeoff.js`)

활주 가속 17m/s² → 72m/s에서 기수 들기(W 또는 S, 1.3초 안에 안 누르면 자동) → 17° 상승, 지면 14m에서 기어 접힘 → 고도 200m에서 미션 시작. 약 11.7초. Enter/Space로 언제든 건너뛴다. 낮음은 막 떠오른 순간부터(약 4.7초).

- 미션 시간·적기 등장·클리어 시간은 이륙 완료(또는 건너뛰기) 시점부터 센다. 이륙 중에는 적기도 피해도 없다.
- 명세에 "W키로 기수를 들어"라고 돼 있지만 게임의 W는 기수 내림이라, 이륙 순간에는 **W와 S 둘 다** 기수 들기로 받는다.
- 고도 하한은 이륙 직후 현재 고도 − 40m에서 시작해 올라가는 만큼 따라 올라가 600m에 닿으면 기존 방식과 같아진다.

## 14. 형상 비교·수정 반복 기록

레퍼런스: 공개 제원(길이 16.9m, 폭 11.2m, 높이 4.7m, 주익 면적 약 46㎡)과 알려진 형상 특징(각진 차인 기수, 캐럿형 측면 흡입구, 잘린 다이아몬드 주익, 바깥으로 기운 쌍수직미익, 전가동 수평미익, F414 쌍발). 웹 검색으로 제원을 확인했고 사진은 게임에 넣지 않았다.

| 차수 | 본 것 | 고친 것 |
|---|---|---|
| 1 | 3/4·상단·근접 캡처 | 동체 글자가 좌우 반전 → 면마다 방향 보정. 수직미익 번호가 한쪽 면에서 뒤집힘 → 대칭 표식으로 교체. 좌석 머리받이가 캐노피를 뚫음 → 낮춤. 삼각형 6.2만 → 분할 배율 올려 9.9만 / 21만 |

## 16. 알려진 한계 · 이후 개선점 (업그레이드분)

- 높음·최고의 실제 프레임률, 조작감, 벤치마크 기준값(4.5ms / 11ms)은 실기에서 확인·보정이 필요하다.
- 구름은 판을 정렬하지 않고 겹쳐 그린다. 색이 비슷해 눈에 띄지 않지만, 아주 가까운 구름과 먼 구름이 겹칠 때 순서가 어색할 수 있다.
- 렌즈 플레어는 구름에 가려지지 않는다(구름은 깊이를 쓰지 않아서).
- 모션 블러는 속도 버퍼 방식이 아니라 이전 프레임을 섞는 방식이다.
- 이륙 후 가만히 있으면 고도 하한 보정만으로 천천히 오른다. 적기는 1,150m 이상에서 나오므로 S로 직접 올라가야 한다.
- 개선 여지: 반매립 미사일·내부 무장창 개폐, 앞전 플랩, 기체 손상 데칼, 적기 종류별 모델, 구름 그림자, 실기 측정에 맞춘 프리셋 재조정, 사운드.

# 모바일·조종사·조작 개선분

## 17. 입력 계층 (`src/core/input.js`, `src/data/input.js`, `src/ui/touch-controls.js`)

키보드·마우스·터치·자이로를 `Input` 하나가 받아서 **조종 축 두 개(pitch, turn)** 와 **조준점 하나**로 정리한다. 세션은 `input.flightAxes()`와 조준 커서만 읽으므로 기기가 달라도 비행·무장 코드는 같다.

- **PC**: 미션 중에는 항상 포인터락. 마우스 이동량으로 가상 조준점을 움직이고(화면 가장자리에서 멈춤), 우클릭을 누르고 있는 동안에는 이동 **속도**가 조향이 된다(px/s ÷ 1200 × 감도, ±1 제한, 0.08초 평활, 멈추면 0.15초 안에 0). WASD가 눌리면 마우스 조향은 무시한다. 잠금이 풀리면(ESC 포함) 자동 일시정지, 잠글 수 없으면 일반 커서 조준으로 폴백한다. 우클릭 메뉴는 항상 막는다.
- **모바일**: 왼쪽 조이스틱(데드존 8%, 지수 1.3, 반지름은 화면 높이 비례) + 자이로(기본 꺼짐, ±30°, 저역 통과, 미션 시작 때 중립 보정)를 **더한** 값이 조종 축이다. 오른쪽 화면을 누른 자리가 조준점이고 누르는 동안 기관포가 나간다. 미사일은 누른 자리가 락온 중심이고, 락온된 뒤 손을 떼면 발사, 락온 전에 떼면 초기화된다. 손가락은 `pointerId`로 구분한다(조이스틱과 조준을 동시에).
- 자동 판별은 `pointer: coarse` + 터치 지원이고 설정에서 PC/모바일을 직접 고를 수 있다. 세로로 들면 회전 안내를 띄우고 멈춘다.

## 18. 락온 0.5초 (`src/data/weapons.js`, `src/combat/lock-on.js`)

락온 시간을 2.0초 → 0.5초로 줄이고, 조준 기준을 화면 가운데가 아니라 **가상 조준점**으로 바꿨다. 표시는 네 모서리가 모여드는 애니메이션(회색 → 주황 → 초록, 완료 때 한 번 맥동). 밸런스 평가는 22절.

## 19. 조종사 (`src/entities/hi/pilot-rig.js`, `src/entities/pilot-low.js`)

- 외부 모델 파일 없이 코드로 만든 `THREE.SkinnedMesh` + `Skeleton`. 뼈: 골반 → 척추 2 → 목 → 머리 / 쇄골 → 위팔 → 아래팔 → 손 → 손가락(5개 × 2마디) / 허벅지 → 정강이 → 발.
- 바인드 포즈에서 모든 뼈의 회전이 단위 행렬이라, 투본 IK는 "기본 방향 → 목표 방향의 최단 회전(`setFromUnitVectors`)"만으로 푼다. 오른손은 조종간, 왼손은 스로틀, 발은 페달에 닿는다.
- 메시는 두 개(팔·손 / 몸·머리·다리)이고 뼈대를 공유한다. 1인칭에서는 팔과 손만 보인다.
- **모델링을 한 번 처음부터 다시 했다.** 첫 판은 타원체를 이어 붙여 헬멧이 공처럼 크고 목이 길게 드러났다. 다시 만든 판은 앉은 인체 치수(눈~어깨 약 0.24m)를 먼저 정하고, 몸통을 단면표(둥근 사각형)를 따라 이은 한 장의 곡면으로 만든 뒤 그 표면을 따라 멜빵·조끼·패치를 붙였다. 헬멧은 얼굴 쪽이 뚫린 껍데기(HGU-55형) + 그 위를 덮는 반사 바이저 + 산소마스크(겉껍데기·밸브·끈) + 주름 호스로 나눴다. 이후 목 길이·옷깃, 손 쥐는 자세(오른손을 세워 잡기, 손목 목표를 손잡이 뒤로), 소매 주머니 크기를 스크린샷을 보며 두 번 더 고쳤다.
- 재질 차이: 비행복(거친 직물 + 주름 노멀맵 + 관절 주름 지오메트리), 장갑(직물 + 가죽 덧댐), 헬멧(무광 도장), 바이저(금속성 반사), 마스크(수지·고무), 금속 버클, 피부(가짜 SSS: 빛을 감싸는 붉은 번짐).
- 동작: G 쏠림은 감쇠가 부족한 스프링(관성으로 늦게 따라가고 되돌아옴) + 큰 G에서 목 눌림. 3인칭에서는 선회 방향으로 고개를 돌리고, 미사일 발사 때 고개를 끄덕이고 엄지가 눌린다. 숨쉬기·눈 깜박임은 없다(헬멧에 가려 보이지 않는다).
- 삼각형: 낮음은 단순 조종사(수십 개), 높음 약 1.6만, 최고 약 4.1만.

## 20. 몰입 요소 (`src/data/extras.js`)

- **킬캠**: 마지막 격추 때 0.3배 슬로모션 2초. 높음·최고(PC)는 격추된 적기를 옆에서 잡는 카메라, 낮음·모바일은 슬로모션만. Enter/Space로 건너뛴다. 결과 화면까지의 지연은 킬캠이 끝난 뒤부터 센다.
- **위협 경고** (`src/combat/threat.js`): 감지기가 "출처" 함수 목록을 물어보고 가장 급한 위협 하나를 HUD에 넘긴다(종류·방위·거리). 지금 출처는 적기 기관포(연발 시작 뒤 1.4초)와 후방 추격(700m 안, 기수 30° 이내)이다. 적 미사일은 `ENEMIES.raider.missileEnabled: false`로 꺼져 있고, 켜면 `enemyMissileSource`를 연결하기만 하면 된다. 화면에는 가장자리 화살표(위 = 정면, 아래 = 뒤)와 WARNING이 나온다.
- **피격 흔적** (`src/entities/decals.js`): 맞을 때 기체 위·아래에서 광선을 쏘아 표면의 점과 법선을 찾고, 인스턴싱한 작은 판(총알 구멍·그을음)을 눕힌다. 드로우콜 1개, 낮음은 8개·높음 이상은 22개까지. 체력이 낮으면 엔진에서 연기가 난다(기존).
- **고도 연출**: 카메라 고도 1,500 → 6,500m에서 하늘 천정색이 짙푸르게, 햇빛이 28% 강하게, 아래에서 올라오는 반사광이 20% 약하게 바뀐다(`WORLD.altitudeLook`).
- **소프트 실링**: 6,000m부터 기수가 눌리고 6,800m 위로는 올라가지 않는다(`data/aircraft.js`). 적기 상한도 5,600m로 낮췄다.
- **튜토리얼** (`src/core/tutorial.js`): 미션 1에서 이륙 → 비행 → 기관포 → 무기 전환 → 시점 전환 → 미사일 락온 순서. 명세의 순서(락온 → 무기 전환)와 달리 무기 전환을 먼저 둔 것은 미사일로 바꿔야 락온을 해 볼 수 있어서다. 문구는 기기별로 다르고, Enter/Space(모바일은 건너뛰기 버튼)로 넘기며, 끝나면 `tutorialDone`이 저장된다. 진행 중에는 미션 시간이 흐르지 않고 마지막 단계에서야 적이 나온다. 점수·시간은 튜토리얼이 끝난 시점부터 잰다.
- **마지막 격추 리플레이** (`src/core/replay.js`): 플레이어와 적기의 위치·회전을 30Hz로 6초 링버퍼(미리 잡은 Float32Array)에 담는다. 임무 완수 결과 화면의 버튼으로 격추 3.6초 전 ~ 1.3초 후를 0.55배속으로 두 번(뒤에서 따라가는 시점 → 표적 옆 시점) 보여 주고 결과 화면으로 돌아온다. 원점 재배치 때는 기록된 좌표도 함께 옮긴다.

## 21. 모바일 성능·화면

- 모바일은 낮음이 기본, 첫 실행 벤치마크를 통과한 기기만 높음을 고를 수 있고 최고는 없다. 해상도 배율 상한 1.5(높음은 2.0), 낮음에서는 구름·파티클을 30% 더 줄인다. 30FPS 아래가 이어지면 자동으로 한 칸 내린다.
- 100dvh, 안전 영역(safe-area), 확대 금지, `touch-action: none`. 버튼은 44px 이상, HUD는 화면 크기에 맞춰 줄이되 글자 크기 하한을 둔다.
- 높이 480px 이하 가로 화면(640×360까지)은 두 칸 배치를 유지하면서 여백과 글자를 줄이고, 일시정지는 설정만 안에서 스크롤하고 버튼은 항상 보이게 했다. 조작 안내는 기기에 맞는 쪽만 보인다.

## 24. 알려진 한계 · 다음에 할 만한 것 (이번 개선분)

- **실제 휴대폰에서 돌려 보지 못했다.** 터치·멀티터치·세로 안내·자이로는 에뮬레이션(CDP 터치 이벤트, 가짜 방향 이벤트)으로만 확인했다. iOS 사파리의 자이로 권한 창, 주소창이 접힐 때의 화면 높이, 화면 방향 고정(`orientation.lock`은 대부분 전체 화면에서만 된다), 실제 프레임률은 실기 확인이 필요하다.
- 포인터락·우클릭 조향의 손맛(감도 기본값, 0.08초 평활)도 실제 마우스로 조정이 필요할 수 있다.
- 조종사: 얼굴은 바이저·마스크에 가려 단순한 형태다. 손은 조종간을 "감싸 쥔 모양"이지 손가락마다 접촉점을 푼 것은 아니다. 1인칭에서 조종간을 끝까지 당기면 팔이 거의 펴진다.
- 킬캠·리플레이의 옆 카메라는 구름·지형에 가려질 수 있다. 리플레이는 기체 자세만 되살리고 탄·미사일 궤적은 다시 그리지 않는다(격추 순간의 폭발만 다시 터뜨린다).
- 피격 흔적은 맞은 위치와 무관하게 기체 위·아래 임의의 자리에 생긴다.
- 위협 경고는 가장 급한 위협 하나만 보여 준다.
- 다음에 할 만한 것: 적 미사일과 회피 수단(플레어), 맞은 방향에 맞는 흔적 위치, 리플레이에 탄 궤적 기록, 모바일 햅틱, 실기 측정에 맞춘 모바일 프리셋 재조정.

### 결정 사항

- **1단계 구멍의 원인**: (a) 부품의 끝이 열린 채 다른 부품 속에 묻혀 있었다(날개·꼬리날개 뿌리와 끝, 덕트 끝, 안테나·파일런 끝. 높음 기준 열린 에지 1,768개). 각도에 따라 안이 들여다보였다. (b) 미사일 몸통의 분할 수가 소수(12 × 배율)라 이음매가 어긋나 있었다. (c) 엔진 베이 끝과 노즐 꽃잎 뿌리 사이에 틈이 있었다.
- **수정 방식**: `src/entities/close-loops.js`의 `capOpenLoops`가 빌드 때 "삼각형 하나에만 속한 에지"를 방향 없이 이어 고리를 찾고, 평평한 고리(평면 이탈 15% 이내)를 귀 자르기 삼각분할로 막는다. 막는 면의 uv·색은 한 정점 값으로 통일한다(평균 내면 텍스처 아틀라스를 가로질러 줄무늬가 생긴다). 하이폴리(`Surf.build`)와 낮음(`GeoBuilder.build`) 모두 적용. `Surf.grid`는 분할 수를 정수로 반올림한다. 엔진 뒤쪽 끝은 막지 않고(`aftSkip`: 막으면 노즐 안으로 면이 비친다) 동체 색 이음 링을 추가했다.
- **검사**: `node tests/open-edges.cjs [low,high,ultra]`. 정점을 1mm로 양자화해 합치고 열린 에지를 센다. 허용 목록은 `tests/open-edges.allow.json`(엔진 후단 한 곳). 투명·양면 재질은 검사에서 뺀다. 세 프리셋 모두 0개.
- **캐노피의 원인**: 메뉴 시네마틱의 첫 장면이 캐노피를 열어 두는데, 그 장면 도중에 미션을 시작하면 열림 값이 그대로 남았다. 또 유리가 정면에서 알파 0.2라 거의 안 보였다. 수정: 미션 시작 때와 미션 중 매 스텝 `canopy = 0`, 유리 알파 0.36~0.95(가장자리일수록 불투명)·색조를 진하게.
- **모바일 프리셋 제한 해제**(사용자 요청): 모바일에서도 높음·최고를 직접 고를 수 있다. 기본은 여전히 낮음이고, 해상도 배율 상한은 낮음 1.5·그 외 2.0, 자동 품질 조절이 켜져 있으면 30FPS 아래에서 한 칸씩 내려간다. 21절의 "최고는 없다"는 이제 맞지 않는다.
- **배포**(사용자 요청): 단계가 끝날 때마다 `main`에도 바로 푸시한다.
- 근접 확인용 시점: `node tests/v2-model.cjs high intakefront,enginerear,under,canopyrear,canopyside,canopytop` (조종사만 볼 때는 `HIDE_CANOPY=1`).
- **검증 최소화**(사용자 요청): 단계마다 `npm test`와 `node tests/smoke.cjs` 정도만 돌린다. 스크린샷·성능 측정은 꼭 필요할 때만.
- **2단계 구조**: `src/mission/engine.js`(순수 로직: 목표 진행·승패·점수), `src/mission/schema.js`(데이터 검증), `src/data/campaigns.js`, `src/data/missions.js`(새 스키마, `define()`이 order·parTime·summary 같은 이전 이름을 채운다). 세션은 `engine.airKill(role)` / `groundDestroyed(type)` / `escaped(role)` / `checkpoint(i)` / `playerDead()` / `tick(dt)`만 부르고 `engine.outcome`으로 승패를 본다. 결과에는 `objectives`(체크리스트), `timeBonus`, `failReason`이 들어간다.
- 수량 목표는 부분 점수(points × 진행/수량)를 준다. 그래서 이식한 c1m1~3의 점수가 예전(격추당 1000 + 남은 시간 × 10)과 같다(`tests/missions.test.js`).
- 미션 ID: `m1~m3` → `c1m1~c1m3`. `missionById`는 옛 ID도 받는다(자동플레이 주소·테스트). 저장은 v2로 올렸고 `normalizeProgress`가 기기·계정 저장을 읽을 때 변환한다. 잠금은 없앴다(`isUnlocked`는 항상 참).
- 편대는 아직 기존 `WaveSpawner`(조건: start / remaining / time)를 쓴다. 미션 데이터의 `at`은 time 조건으로 바뀐다. 역할(`role`)·성격(`personality`)은 6·7단계에서 스포너가 읽게 한다.
- **3단계 지면**: 따로 지상 패치 메시를 만들지 않았다. 원경 지형 셰이더가 활주로 주변을 평평하게 누르는 반경을 2.3km → 9.5km로 넓혀 미션 구역 전체가 활주로 표고(42m)의 평지다. 그래서 `getGroundHeight(x, z)`(`src/world/ground.js`, 순수 함수, 실제 좌표)는 상수이고 보이는 땅과 정확히 맞는다(추가 삼각형 0). 굴곡 있는 지면이 필요해지면 이 함수와 셰이더를 같은 식으로 바꿔야 한다.
- **바다**(`terrain: 'coast'`): 해안선은 활주로 앞 4.2km의 직선(`GROUND.coastZ`). 그 너머를 삼각형 2개짜리 평면이 덮고 물결은 셰이더가 만든다. `isSea(x, z)`로 판정한다. 함정은 `getGroundHeight`가 돌려주는 수면 높이에 놓는다.
- **고도 하한**: 지면 기준 100m(`floorHard: 142`), 경고는 330m 아래. 적기 하한도 420m로 낮췄다.
- **시간대**(`src/data/timeOfDay.js`, `world.setEnvironment(시간대, 지형)`): 하늘 4색·해(달) 방향·색·세기, 반사광, 안개, 구름 색, 지형 색조, 별(하늘 셰이더), 노출을 바꾼다. 미션 시작 때 한 번 부르고, 시간대가 바뀌었을 때만 `visuals.refreshEnv()`로 환경맵을 다시 굽는다. `world.look.lights`(조명 배율)·`hud`는 값만 준비돼 있고 4단계(목표 조명)·9단계(HUD)에서 읽는다. 확인: `node tests/e3-env.cjs`, 디버그 훅 `__debug.env('night', 'coast')`.
