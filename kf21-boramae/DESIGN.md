# KF-21 BORAMAE — 설계 메모

3D 전투기 슈팅 MVP. Three.js + Vanilla JS(ES Modules) + Vite. 주소: `https://09jun4.github.io/kf21-boramae/`

## 1. 실행 · 배포 방식 (결정 사항)

- 이 저장소는 빌드 없이 `main`에 올리면 바로 GitHub Pages로 나가는 구조다. 그래서 **배포본 = 소스 그대로**로 했다.
  - `index.html`의 `importmap`이 `three`를 `js/vendor/three.min.js`(한 파일로 묶어 둔 three.js)로 연결한다.
  - 나머지는 브라우저가 `src/`의 ES 모듈을 직접 읽는다. 코드를 고치고 push하면 그대로 배포된다.
- Vite는 개발 도구로 쓴다: `npm run dev`(개발 서버), `npm run build`(한 파일로 묶은 `dist/`, 선택), `npm test`(Vitest 단위 테스트), `npm run smoke`(Playwright 스모크), `npm run vendor`(three.js 다시 묶기).
- 외부 3D 파일·이미지·폰트는 없다. 모델·구름·지형·효과는 모두 코드로 만든다.
- 디버그 훅 `window.__debug`는 개발 서버이거나 주소에 `?debug=1`이 있을 때만 켜진다(`src/core/debug.js`).

## 3. 핵심 알고리즘

- **게임 루프**: 누적기 방식 고정 타임스텝(60Hz). 프레임 델타는 0.1초로 상한(탭 복귀 시 시간 점프 방지). 렌더는 이전/현재 상태를 `alpha`로 보간.
- **비행 모델**: 상태는 (위치, 요, 피치, 시각 롤, 속도). 입력 → 목표 각속도 → 지수 감쇠로 실제 각속도(관성). 속도는 `추력−항력`을 순항속도로 끌어당기는 스프링 + 중력 성분(상승 감속/하강 가속) + 선회 항력. 속도 하한 근처에서는 상승 권한이 줄고 기수가 숙여진다(실속 사망 없음). 고도 하한·상한은 허용 피치 범위를 부드럽게 좁혀서 처리한다.
- **원점 재배치**: 플레이어가 원점에서 일정 거리 이상 벗어나면 모든 개체를 x·z로 되돌린다(y는 고도라 범위가 한정됨). 지형·구름은 누적 오프셋을 유니폼으로 받는다.
- **구름**: `InstancedBufferGeometry` 1~2 드로우콜. 구름 묶음 위치를 버텍스 셰이더에서 카메라 기준으로 순환(wrap)시켜 CPU 갱신 없이 무한 하늘을 만든다. 가장자리에서는 크기를 줄여 튀는 현상을 숨긴다.
- **원경 지형**: 격자 1장. 버텍스 셰이더에서 월드 좌표 노이즈로 높이를 만들고, 프래그먼트에서 미분으로 플랫 셰이딩 + 거리 안개.
- **기관포**: 카메라→커서 레이로 조준점을 구하고, 그 레이에 대해 적기 구(거리 비례 보정 반경)와 교차 판정(즉시 판정). 예광탄은 총구→조준점으로 그리는 연출.
- **미사일 락온**: 화면 중심 기준 각도 반경 안의 적 중 가장 중심에 가까운 적을 추적, 유지 시간 누적으로 락온. 반경 이탈 시 즉시 초기화.
- **미사일**: 실제 이동 발사체. 목표 방향으로 초당 최대 선회각 제한 회전, 수명·근접 신관.
- **적 AI**: 상태(접근/공격/이탈/회피/복귀) + 목표 방향을 각속도 제한으로 따라가는 조향 + 적기 간 분리 벡터. 동시 공격 수 제한(공격 토큰)으로 공정성 유지.
- **메모리**: 메시·풀은 시작할 때 한 번만 만들고 미션마다 상태만 초기화한다. 프레임 중 할당 없음(임시 벡터 재사용).

## 5. 결정 사항 (명세에 없어서 정한 것)

- **미사일 락온 범위의 중심은 화면 중심**이다(명세의 "화면 중심 기준"). 기관포는 마우스로 자유 조준, 미사일은 기수를 적기 쪽으로 돌려야 락온된다. 두 조준 방식이 독립적이고 역할이 갈린다.
- **마우스 감도**: 포인터락을 쓰지 않으므로, 조준 커서를 화면 중앙 기준으로 `감도` 배만큼 움직이는 방식으로 구현했다(1.0이면 실제 커서 위치).
- **과열 잠금 2.5초 동안에도 냉각은 진행**된다(쏘지 않는 동안 초당 30%). 잠금이 풀리면 약 25%에서 다시 쏠 수 있다.
- **미사일은 클릭하는 순간에만 발사**된다(누르고 있어도 연달아 나가지 않는다).
- **충돌로 파괴된 적기도 격추로 센다.**
- **적 탄은 실제 발사체**다(피할 수 있다). 조준은 탄 비행시간과 플레이어 가속도까지 반영해서, 같은 방향으로만 계속 돌거나 올라가면 맞는다.
- **고도 상한(9,500m)**을 뒀다. 속도 저하와 함께 "무한 상승으로 도망"을 막는다.
- **적기 식별**: 붉은 외곽선(화면 약 1.5픽셀 고정) + HUD의 붉은 모서리 상자. 모델은 실물보다 1.35배.
- **피치 한계 ±75°**: 루프(수직 넘김) 기동은 없다. 요+시각 롤 조작 체계에서 방향 감각을 잃지 않게 하기 위해서다.
- **설정의 계정 연동**: 마우스 감도·흔들림·시점은 계정에 저장하고, 그래픽 품질은 기기마다 다른 게 자연스러워 이 기기 값만 쓴다.
- **재시작**은 브리핑 없이 같은 미션을 바로 다시 시작한다.

## 7. 성능·메모리 측정값

`node tests/perf.cjs` (미션 3 + 적기 8대 + 연사 + 폭발 4개가 겹친 순간의 최대값):

| | 드로우콜 | 삼각형 | 예산 |
|---|---|---|---|
| 높음 | 31 | 약 116k | 150 / 200k |
| 낮음 | 29 | 약 74k | 80 / 100k |

- 미션 시작→전투→종료를 12회 반복한 전후: 지오메트리 23→23, 텍스처 1→1, 셰이더 15→15, JS 힙 +0.15MB(증가 추세 없음).
- 그림자·포스트프로세싱 없음. 구름·파티클·예광탄·적 탄은 InstancedMesh, 미션마다 재생성하지 않음.
- **FPS는 개발 환경(GPU 없는 서버, 소프트웨어 렌더링)에서 잴 수 없었다.** 실제 노트북에서의 60/45FPS 목표는 드로우콜·삼각형 예산과 자동 품질 조절로 대비했지만 실기 측정은 하지 못했다. `?debug=1` 뒤 콘솔에서 `__debug.showFps()`로 확인할 수 있다.

## 8. 알려진 한계

- **랭킹 부정 방지는 완전하지 않다.** 점수를 클라이언트가 올리는 구조라 조작된 요청을 막을 수 없다. 보안 규칙에서 타입·범위·점수식(1000×적기 수 + 남은 시간×10)과 최소 시간(8초)을 검증하고, 관리자가 랭킹 창에서 기록을 지울 수 있게 해서 대응한다.
- **보안 규칙은 실행 검증하지 못했다.** 로그인·이관·닉네임·랭킹 흐름은 가짜 SDK로 확인했고, 규칙 자체는 실제 Firebase 프로젝트에 게시한 뒤 확인이 필요하다.
- **등급**: 명세의 비율(S 90% / A 75% / B 55%)과 점수식을 그대로 쓰면, 전원 격추만으로 기준 점수의 약 77%가 되어 성공 시 등급은 항상 A 이상이다. 비율은 `src/data/grades.js`에서 바꿀 수 있다.
- **닉네임 금칙어**는 짧은 목록으로 거르는 수준이다.
- **조작감·난이도는 사람이 아니라 자동 조종으로 검증했다.** 수치 기준(반응 시간, 지속 상승각, 수평 복귀 등)은 단위 테스트로 확인했지만, 손맛에 대한 최종 판단은 실제 플레이가 필요하다.
- 사운드는 범위 밖이라 `core/audio-stub.js`의 `audio.play(name)` 호출 지점만 있다.
- 모바일 조작은 지원하지 않는다(범위 밖).
